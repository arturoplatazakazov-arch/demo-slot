# Big Catch — арт

Нарезка из макета Figma («BIG CATCH», секции Slots и POP-AP). Сырьё лежит в
`src/` и в git НЕ уходит (см. `front/img/*/src/` в .gitignore); в репозитории
только `img/` и `symbols/`, ужатые PIL FASTOCTREE до 224 цветов
(9.1МБ -> 1.7МБ, на глаз в рендере разницы нет).

## Что важно знать, если перережут

* Все символы уложены в общий бокс **202x202** — это ячейка из макета. Сам
  арт внутри 190x190, скаттер 202x202 (он специально шире ячейки и заезжает на
  канаты). Клиент рисует бокс как 202/197 от ячейки, поэтому пропорции из
  Figma сохраняются один в один; менять размер холста нельзя, не поправив
  `.reel__cell img` в стилях.
* `reel_ropes.png` НЕ макетный: у дизайнера оси канатов стоят с шагом
  209 / 190 / 209 по X и 190 по Y, то есть ячейки выходили разной ширины
  (первый барабан на 14px уже пятого). Файл пересобран из его же плетения:
  чистый кусок каната размножается с шагом 13px (период плетения) вдоль осей,
  посчитанных ОТ СЕТКИ — 256.5 / 454.5 / 652.5 / 850.5 по X и 272.5 / 470.5
  по Y от угла рамки. Холст = бокс рамки 1110x723, отрисован в 2x. Оригинал
  из Figma лежит в `src/reel_ropes_figma.png`.
* Проём `reel_frame.png` померен по альфе: 989x593 при отступах 59/75/62/55 от
  краёв картинки 1110x723. Эти шесть чисел продублированы в
  `front/css/big-catch.css` (`--frame-border-*`) — перережут рамку, мерить
  заново.
* Пустые панели плашек попапов померены по арту и лежат в
  `--popup-panel-*`. Туда клиент ставит сумму (или число спинов в бейдже);
  заголовки в плашки уже впечатаны и DOM'ом не рисуются.
* На нижней доске указателя в макете стояла статичная цена «10 000 000 USD».
  Её пришлось стереть (доска восстановлена морфологической фильтрацией по
  строкам), потому что настоящая цена = ставка x100 и меняется вместе со
  ставкой — её пишет DOM, см. `.sign-buy-bonus__price`.


## export/ — Spine-анимации символов

Скелетов ЧЕТЫРЕ, а не десять: `common` и `rare` — это по одному скелету с
четырьмя скинами, `scatter` и `wild` — свои. Дизайнер прислал по папке на
символ (`common_1..4`, `rare_1..4`), но внутри лежали побайтово одинаковые
файлы; лишние копии убраны в `src/export_raw/`. Имена приведены к общему для
репозитория виду `animation.atlas` / `animation.json` / `animation.png`
(вместе с первой строкой атласа — она обязана совпадать с именем PNG, иначе
вендорный рендер-луп молча не стартует, см. `_ensureRenderLoop` в
`front/js/spine-engine.js`).

| папка | скины | символы | idle / land / win |
|---|---|---|---|
| `export/common` | common_1..4 | bobber, tacklebox, hat, lure | 2.6 / 0.44 / 1.6 c |
| `export/rare` | rare1..4 | marlin, puffer, bass, pike | 3.0 / 0.46 / 1.8 c |
| `export/scatter` | — | scatter | 3.6 / 0.74 / 2.4 c (обновлён 1.09: +слоты word/clip_g/spark0..4, текстура та же) |
| `export/wild` | — | wild | 3.2 / 0.70 / 2.0 c |

Соответствие скинов символам — в `SYMBOL_SPINE` (front/js/big-catch/slot.js).

**Почему статики берутся из экспорта.** `static_*.png` — это рендеры той же
сцены, отцентрованные по началу координат скелета на холсте 200x200 (у
скаттера 226x226). Клиент ставит начало координат скелета в центр ячейки и
рисует его в нативный масштаб, а картинку — в её собственный размер, поэтому
подмена «статика <-> анимация» проходит без скачка: замеряно, расхождение
центров и габаритов не больше 1.5px макета по всем девяти символам.

Приземления (`land`) в игре НЕ проигрываются — продукт убрал их у всех
символов; клип в экспортах остался, но клиент его не трогает. Idle крутят все
десять символов, фаза у каждой ячейки сдвинута случайно, иначе одинаковые
символы дышат синхронно.

**Чего в экспорте не хватает** (не блокирует, но лучше донести):
* `static_common_3.png` (панама) не приехал — собран из атласа по координатам
  скина common_3, поэтому совпадает со скелетом точно так же, как остальные.
